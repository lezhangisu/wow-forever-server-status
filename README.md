# WoW Forever 测试服 · WoW Server Status

一个不依赖第三方包的轻量状态页。Node.js 后台每 **45 秒**对两个域名和八个世界节点各建立一次 TCP 连接，连接成功后立即关闭，不发送登录或游戏数据。网页每 **60 秒**读取一次缓存的检测结果，不会因访客数量增加而重复探测目标服务器。页面和公开状态接口只提供总体及三个阶段的概况，不展示具体节点、连接数量或延迟。

页面默认使用中文，右上角可以切换中英文。“手动刷新”会立即读取后台最新一次检测结果，并重置页面的 60 秒更新倒计时；它不会额外探测游戏服务器。

主状态卡片下方有状态历史时间轴，可切换 **2 小时、24 小时、30 天**，默认展示 2 小时。鼠标悬停或键盘聚焦后使用方向键，可以查看对应时刻及宏观状态。后台将每次检测的宏观状态写入 `data/history.jsonl`，公开接口只返回时间段与宏观状态。历史最多展示最近 30 天；未运行监测或尚无记录的时间段显示为灰色。首次启用前的状态无法追溯。可用 `HISTORY_FILE` 环境变量更改存储路径。

## 运行

需要 Node.js 20 或更新版本：

```sh
npm start
```

本机打开 <http://127.0.0.1:3000>。通过环境变量设置监听地址和端口，例如 `HOST=0.0.0.0 PORT=3000 npm start`。公开部署时，建议在服务前放置 HTTPS 反向代理。服务本身没有外部运行依赖，内存中只保留最新一次检测结果。

也可以用 Docker 运行：

```sh
docker build -t wow-test-status .
docker run --rm -p 3000:3000 -v wow-status-data:/app/data wow-test-status
```

部署机器需要能够解析并连接两个域名，以及连接世界服务器 IP。当前目标为 `oauth.integration.battle.net:443`、`prod.depot.battle.net:443`，以及 `66.40.176.132:3724`、`66.40.176.178:3724`、`66.40.177.113:3724`、`66.40.178.104:3724`、`66.40.178.154:3724`、`66.40.178.196:3724`、`66.40.179.205:3724`、`66.40.179.232:3724`。前两个域名基于抓包线索指定；其 443 端口可连接只说明 TCP 入口可用，不能证明实际完成账号验证或角色信息获取。世界服务器 IP 若变化，可在 `lib/monitor.js` 中更新。

## 状态规则

| 等级 | 条件 |
| --- | --- |
| 红 · 服务器离线 | 登录验证端口无法连接 |
| 橙 · 登录受限 | 登录验证端口可连接，角色信息端口不可连接 |
| 红 · 游戏服务不可用 | 前两阶段可连接，但世界节点在线数不超过总数的一半 |
| 黄 · 世界服务受限 | 前两阶段可连接，世界节点在线数超过一半、但少于 N−1 |
| 绿 · 服务器在线 | 前两阶段可连接，世界节点在线数至少为 N−1 |

N 为监测的世界节点总数。当前 N=8，因此 0–4 个可连接为不可用，5–6 个为受限，7–8 个为在线；当 N 为偶数时，恰好一半可连接归入不可用。

单次连接超时为 3 秒。状态只反映运行本服务的机器到这些端口的 TCP 连通性；防火墙、路由、服务端限流和服务器 IP 变化可能影响判断。端口可连接也不能保证完整登录或游戏流程一定成功。
